## moonstone-ace: what it is

Moonstone (Mindscape, 1991) rebuilt as C++ on the ACE engine, targeting A1200 (68020/AGA). It began as a decompilation of the
68k disassembly: reassemble the original, link it with an ACE runtime, lift routines to C++ one at a time, each verified
against the original. Since ROADMAP 7.1r the whole game is C++ and no original asm is linked. Docs: `README.md`, `BUILD.md`,
`ROADMAP.md`, `docs/*.md` (module map `docs/MODULES.md`, label index `docs/LABEL_INDEX.md`, modding `docs/MODDING.md`,
publishing rules `docs/PUBLISHING.md`, repository move `docs/MIGRATION.md`). **ROADMAP.md is the source of truth for status and
task numbers**; task numbers (`ROADMAP 2.7`, `3.2`) are cited from code and docs: never renumber, add `Na` suffixes instead.

**This repository contains nothing of the original game** (no code, art, data, disassembly or disk image), by design
(`docs/PUBLISHING.md`, `tools/publish.txt`, `tools/leakscan.py`). The game reads the player's own disks when it starts. Never
add original material to a tracked file: no byte tables pasted from the disassembly, no game texts, no screenshots of
original art, no disk images. `py tools/leakscan.py` (also a step of `tools/integrate.py`) must stay clean.

## Layout

- `ace/` is the ACE engine as a git submodule (pinned; `git clone --recursive`). `tools/toolchain/`,
  `tools/AmigaCMakeCrossToolchains/`, `tools/bartman_gcc_support/` (pinned to one revision, `tools/dev_setup.py`) are local,
  git-ignored links/copies of the cross toolchain.
- `private/` is git-ignored developer-only material (never published): the IRA listing `nb/program/mog.asm`
  (`private/reference/moonshard/moonstone-main/amiga_asm`), the reassembly `asm/*.s` + patch tables, `src/lifted`, the lifting
  tests, the disk images. `py tools/dev_setup.py --from <archive>` fills it and materialises it into the tree
  (`reference/`, `asm/`, `src/lifted/`, `tests/test_lift.py`, `tests/test_diffharness.py`: all git-ignored). Without it
  every tool that needs the listing prints "skipped: needs the IRA listing" and the unit tests skip; nothing else changes.
- `build/` holds git-ignored generated and original-derived files, **including the extracted disks (`build/disks`, `build/adf`)
  and the screenshot references (`build/shots/ref*`), so `build/` is not disposable**. `build-*/` are further build trees.

## Commands (run from the repository root; the toolchain PATH is in `BUILD.md`)

```sh
py tools/check.py            # the milestone gate: unittest, resource --verify, routines, run_host replay, status drift, lift survey
py tools/check.py --quick    # skip replay and builds
py tools/check.py --builds   # also build build, build-debug, build-game-debug, build-enh, build-synth (those that exist)
py -m unittest discover tests                            # all unit tests
py tools/integrate.py --boot --tests auto                # build, tests, headless boot regression (WinUAE)
py tools/leakscan.py                                     # nothing original in a tracked file
py tools/setup.py A.adf B.adf C.adf                      # extract the disks into build/ (+ build, hdinstall)
py tools/dev_setup.py --from <archive>                   # developer-only material into private/ (docs/MIGRATION.md)
```

Steps of `check.py` / `integrate.py` that need the IRA listing (resource, routines, replay, lift survey) are reported as
skipped when `private/` is not set up; that is expected in a plain public clone.

Builds (configure lines in BUILD.md): `build/` Release LTO, `build-game-debug/` Debug, `build-autoplay/` (headless boot tests,
`py tools/integrate.py --boot`), `build-enh/` (64 colours), `build-synth/`. `cmake --build build-game-debug --target hdinstall`
then run `moonstone-ace-hd.uae` in WinUAE (A1200/KS3.1; the Debug exe needs fast RAM).

## Architecture

The game is all C++: `src/engine` (pure logic), `src/game` (rules/scenes), `src/rt` (ACE runtime + hardware); data hunks are
generated by `tools/gen_data.py` into `build/gen`. Overlays never return; entry is `src/rt/game.cpp`. The start-up fill
(`src/rt/origload.cpp`, `src/engine/origfill.cpp`) copies the original data from the player's disks into the C++ objects.

- **Generated, don't hand-edit:** `include/ms/gen/*`, `src/rt/gen/*`, `src/rt/{abs_stubs,image_tab}.cpp`, the `status:` field of
  `tools/symbols.yaml` (only `tools/status.py` writes it), and (developer checkout) `asm/*.s` and `src/lifted/**`.
  `tests/test_resource.py::test_generated_files_in_repo_are_current` enforces the first group when the listing is there.
- **Status ladder:** `asm` -> `lifted` -> `idiomatic` -> `native`; `src/lifted` + the diffharness are only a test oracle now.
- Merges go through `py tools/integrate.py --boot --tests auto`.

## Rules for changes here

- The original behaviour is the reference (the disassembly in `private/`, the disks); the C ports of the moonshard project are
  only cross-checks. Behaviour stays bit-identical; the code should read as readable, pattern-shaped C++ (small single-concern
  modules, state machines for scenes, table-driven data, pure host-testable rules, one owner per fact).
- Behaviour-changing tasks end with a `build/shots/` screenshot or a replay log named in the result note.
- C++ is `-fno-exceptions -fno-rtti`, no STL, no `new`/`delete`, global constructors don't run. Never add `-fno-omit-frame-pointer`
- Resources use RAII: every acquire/release pair (files, memory marks, scene slots, OS access, IRQ/DMA/blitter ownership, display
  state saves) is a stack-only, non-copyable guard whose destructor releases (global constructors don't run, so no static guards).
  (GCC 15.1 ICE in bartman_gcc_support).
- AmigaOS text files need LF-only line endings (a CRLF `startup-sequence` silently breaks boot); Windows CMake text writes are
  CRLF, so the startup-sequence is written via Python.
- Parallel work uses git worktrees under `wt/` (git-ignored) with `py tools/worktree_setup.py --path wt/<name>`; each agent uses its
  own `MS_BOOT_INSTANCE` for `uaeshot.ps1` (see `docs/MIGRATION.md`, "Worktrees and agents").
- Commit only explicit paths; never commit `build*/`, `private/`, disk images or anything extracted from them.
