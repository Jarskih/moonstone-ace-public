# Agent brief (moonstone-ace)

Read this before any task in `moonstone-ace/`. Task prompts point here instead of repeating it.

## Read first
`D:\Amiga\CLAUDE.md`, `D:\Amiga\AGENTS.md` (toolchain PATH), `ROADMAP.md` (your task number and the notes under it),
`docs/PATCHES.md` (patch format, patch-local `funcs`, integrate/bisect/worktree tools), `docs/ASM_REMAINING.md` (what asm is
still live; `py tools/asm_remaining.py --list mog|program`). Asm authority: `D:\Amiga\moonshard\moonstone-main\amiga_asm\{nb,program,mog}.asm`.

## Never touch
`src/lifted/**`, `tools/lift*.py`, `tools/diffharness/**`, `tests/test_lift.py`, `tests/test_diffharness.py`,
`tools/symbols.yaml`, `README.md`, `BUILD.md` (another session owns them). Do not commit. Do not renumber ROADMAP tasks.
Leave `ROADMAP.md`, `CMakeLists.txt` and `asm/patches/abs_symbols.json` to the integrator unless your task says otherwise;
report needed changes as diffs.

## Work in your own worktree
`py tools/worktree_setup.py --path D:/Amiga/wt/<task>` from HEAD, work and test there, report the changed file list. Your
half-done patch files then never leak into the integrator's builds.

## Patches
New area = new files: `asm/patches/<bin>.<area>.json` with its own `"funcs": [{"name", "impl"}]`. Lines are 1-based in the
moonshard asm, `orig` exact, `new` no more bytes than `orig`, no overlap with any existing range (add a test that checks it).
Retire executed-never DC blocks with `as_data` patches. Verify: `py tools/resource.py --verify --no-write`.

## Code
Idiomatic C++ (`-fno-exceptions -fno-rtti`, no STL, no new/delete, no global constructors; only PC-only files in `src/rt/sdl/`
may use the C++ standard library, `tests/test_pc_stdlib.py`, and are written in modern C++23: see `docs/PC_PORT.md` "Modern C++
in PC-only files"). Pure logic in `src/engine` or
`src/game` (host-testable), hardware/asm glue in `src/rt` (no asm is linked since ROADMAP 7.1r: a `prg_`/`mog_` name in C++, or a name of `tools/cell_names.yaml` (`mogCurKnight`, ROADMAP 7.1s: add names there, `py tools/rename_cells.py --apply`), is a C++-owned cell,
generated by `tools/gen_data.py` from `extern_data` / `extern_cells`; a code-hunk cell you need is added to `asm/patches/<bin>.data_cells.json`, docs/PATCHES.md).
Shims keep the original register contract; document it in the file. Reproduce original quirks and comment them;
list deliberate differences in your report.

## Tests
Host tests with `clang++` (no STL): compare against a Python model of the asm and/or the lifted 68k oracle
(`tools/lift.py`, run it, never edit it); shims vs original in unicorn (pattern: `tests/test_sfx.py`, `tests/test_input.py`).
Prove sensitivity with one deliberate mutation. Compile-check new m68k code with `m68k-amiga-elf-g++`.

## Fast loop (BUILD.md "Fast loop for agents")
After each change `py tools/check.py --changed` (only the test modules the change touches, parallel, the host-clang compile cache on);
before you report `py tools/check.py --quick` (all modules in parallel, **mutation tests off**). Mutation tests (a deliberate bug, a driver
recompiled) run only with `py tools/check.py --mutations` / `MS_MUTATIONS=1`: a new one needs "mutat" in its class or method name (or
`@mutation_gate.mutation_test`) to be gated. A single module: `py tools/testrun.py test_x`. Several agents share this machine's CPU: do not
start a second full run while one of yours is going, and run the timing-sensitive checks once.

## No emulator runs (owner 2026-10-10)
Task agents do **not** run WinUAE: no `uaeshot.ps1`, no `integrate.py --boot`, no play scripts. Write the code, host tests,
Amiga compile and `py tools/check.py --quick` only. The integrator merges a batch and runs the boot/play scripts once for the
batch (`docs/AUTOPLAY.md`; that batch holds the machine-wide emulator lock, `tools/emulock.py`, BUILD.md). Only a task that is itself a measurement may do one final emulator session, and its brief says so.

## Report
Concise: what was ported (label -> function), what stays asm and why, files, patch-local funcs, CMake/abs diffs, register
contracts, test results, boot checks the integrator should run.
