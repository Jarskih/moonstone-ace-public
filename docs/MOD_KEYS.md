# Mod keys

Generated by `py tools/gen_moddata.py --doc docs/MOD_KEYS.md` from `tools/mod_schema/*.yaml`: do not edit by hand
(`tests/test_gen_moddata.py` checks it is current). The files live in `PROGDIR:mods/`; format and rules in
`docs/ARCHITECTURE.md` section 3. A missing file or key keeps the built-in value; a file with an error is ignored
as a whole. The complete reference with every key at its built-in value is generated into `build/gen/defaults/`
(`hd/mods/defaults/` on the hard disk install). Built-in values are not listed here.

## arenas.ini - Creature arenas (the fights of the lairs)

### `[arena <name>]`

The creature arenas: what a lair fight is made of. The built-in rows are the original arenas (named after their creature). A row starts from the built-in arena `like` names and changes what you set. A lair uses an arena through its slot in the arena table (`arena` of lairs.ini): the built-in rows keep their slots; a new row (`base = <row>` first) needs a free `slot` (10, 11, 13 or 15). A new monster in a lair: a creature row (creatures.ini), an arena row whose `creature` is that row's number, and a lair row whose `arena` is the arena's slot. The `demon` row is the guardian's arena: it honours only `creature` and `palette`.

Built-in rows: be, mudmen, demon, trogg_axe, trogg_axe_b, trogg_spear, ratmen, balok, troll. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 13 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `like` | enum | be, mudmen, demon, trogg_axe, trogg_axe_b, trogg_spear, ratmen, balok, troll | The built-in arena this row starts from (its loader, spawn lists and script changes). |
| `slot` | int | -1..16 | The slot of the arena table the row is stored in (the number a lair row names as `arena`). -1 keeps the built-in slot; a new row needs a free one: 10, 11, 13 or 15. |
| `creature` | int | -1..15 | The creature that spawns: its row number in creatures.ini (built-in rows 0-9 in the order be, mudmen, trogg_axe, trogg_axe_b, trogg_spear, ratmen, balok, troll, demon, dragon; new rows follow in the order of the file). -1 = the built-in arena creature. |
| `alive_max` | int | -1..20 | Monsters alive at the same time, before the wave scaling of rules.ini. |
| `total` | int | -1..60 | Monsters in the fight in all, before the wave scaling (a lair fight takes its own count, lairs.ini). |
| `palette` | int | -1..255 | The palette kind of the fight screen (the colours of the arena). |
| `cels` | enum | original, trogg_axe, trogg_spear, ratmen, mudmen, balok, be, troll, dragon, demon | The cel set (the pictures of the monsters) the arena loads, by the name of the original monster set. A new monster's own pictures come with the monster kit (ROADMAP 9.8); until then a variation can borrow another monster's set. |
| `sounds` | enum | original, balok, dragon, be, demon, troll, trogg_spear, ratmen, mudmen | The sound bank (the creature sounds) started with the cel set, by the name of the original monster's bank. |

### `[creature <name>]`

The monsters of the arena fights. The built-in rows are the original creatures; a new row (`base = <row>` first) is a variation. A row starts from the built-in record named by `like` (its own by default) and then applies the keys you set, so a new creature needs only what differs. Tables and scripts are shared by name: a creature that uses another's walk table walks like it; new scripts and tables come with the script editor (ROADMAP 8.8). A creature appears in a lair through an arena row (arenas.ini, `creature`).

Built-in rows: be, mudmen, trogg_axe, trogg_axe_b, trogg_spear, ratmen, balok, troll, demon, dragon. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 16 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `like` | enum | be, mudmen, trogg_axe, trogg_axe_b, trogg_spear, ratmen, balok, troll, demon, dragon | The built-in record this creature starts from (its tables, scripts and numbers); the keys below change it. |
| `ai` | enum | original, flyer, snatcher, demon, dragon, brawler, brawler_b, spearman, caster, drake, stalker | The behaviour (AI) the creature fights with; the engine's fighter types by name. `original` keeps the built-in one. |
| `hp` | int | -1..999 | Hit points at the start of the fight (-1 = the original). Also the maximum unless `hp_max` is set. |
| `hp_max` | int | -1..999 | Maximum hit points (-1 = the same as `hp` when that is set, else the original). |
| `reach` | int | -1..999 | How close it comes before it attacks (-1 = the original). |
| `too_close` | int | -1..999 | The distance it backs off from (-1 = the original). |
| `depth` | int | -1..999 | How far apart in depth it can still hit (-1 = the original). |
| `idle` | enum | a name of the `script` list (docs/MOD_KEYS.md) | The script it stands with (`original` keeps the built-in one). |
| `alt` | enum | a name of the `script` list (docs/MOD_KEYS.md) | The second standing script (`original` = the built-in one, or the idle script when `idle` is set). |
| `hurt_table` | enum | a name of the `hurt_table` list (docs/MOD_KEYS.md) | The table of scripts played when it is hit. |
| `walk_table` | enum | a name of the `walk_table` list (docs/MOD_KEYS.md) | The table of walk scripts. |
| `action_table` | enum | a name of the `action_table` list (docs/MOD_KEYS.md) | The table of action scripts. |
| `damage_table` | enum | a name of the `damage_table` list (docs/MOD_KEYS.md) | The table of the damage it deals; `damage` writes into it. |
| `damage` | list | list of 0..9 (numbers -1..999) | The damage per action slot 0..8 written into the creature's damage table when the game starts (-1 leaves a slot as it is). The table is the one named by `damage_table`, or the built-in one; creatures that share a table share the change. |

## items.ini - Weapons, armour and stat items

### `[weapon <name>]`

The weapons a knight can wield (Knight sword code). The built-in rows are the four swords; a new row needs its own `code`. Rules look a weapon up by its code, so a row changes behaviour for everything that wields it.

Built-in rows: long, broad, claymore, sharpness. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 8 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `code` | int | 1..255 | The item code stored in the knight's sword field that selects this weapon. Must be unique among the weapons. |
| `price` | int | 0..32767 | Smith price in gold; 0 means the smith does not sell it. |
| `damage` | int | 0..255 | Damage added to every hit of a knight wielding the weapon. |
| `rank` | int | 0..255 | Order of strength. The smith only offers a weapon ranked above the one the knight already has. |
| `kind` | enum | melee | How the weapon attacks. Only melee exists today. |

### `[armour <name>]`

The armours a knight can wear (Knight armour code). The built-in rows are the four armours; a new row needs its own `code`.

Built-in rows: padded, mail, plate, battle. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 8 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `code` | int | 1..255 | The item code stored in the knight's armour field that selects this armour. Must be unique among the armours. |
| `price` | int | 0..32767 | Smith price in gold; 0 means the smith does not sell it. |
| `hp` | int | 0..255 | Maximum hit points added while the knight wears it. |
| `endurance` | int | 0..255 | Derived endurance added while the knight wears it (a turn lasts longer with more). |

### `[item <name>]`

Inventory items that change a knight's stats. `slot` is the inventory byte (even offset 0..22) that holds the item's count. A row with neither a hit point bonus nor a forced weapon does nothing.

Built-in rows: protection_ring, sharp_sword. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 8 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `slot` | int | 0..22 | Inventory byte offset of the item's count (even). |
| `hp` | int | 0..255 | Maximum hit points added per item held. |
| `forces_weapon` | int | 0..255 | Weapon code the knight is forced to wield while holding at least one of the item (0 = none). A knight who holds the sharp sword always wields the sword of sharpness. |

## lairs.ini - Lairs and their loot

### `[lair <name>]`

The 24 lairs of the map, in the order of the game (`lair01` first). A game started with a lair row set uses it instead of the original: which creatures live there (`arena`), how many (`count`), where it is drawn (`x`, `y`) and its map region. The rows are fixed: no lair can be added or removed. Without a value (-1) the original is used.

Built-in rows: lair01, lair02, lair03, lair04, lair05, lair06, lair07, lair08, lair09, lair10, lair11, lair12, lair13, lair14, lair15, lair16, lair17, lair18, lair19, lair20, lair21, lair22, lair23, lair24. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 24 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `arena` | int | -1..16 | Which of the game arenas (monster kinds and fights) the lair uses, 0 to 16, the position in the arena table. |
| `count` | int | -1..60 | How many monsters the lair holds when the game starts (the fight scales it with the knight's strength). |
| `x` | int | -1..351 | Where the lair is drawn on the map, x. |
| `y` | int | -1..199 | Where the lair is drawn on the map, y. |
| `region` | int | -1..255 | The lair's map region word (which terrain pictures its fight uses). |

### `[loot_odds <name>]`

What a lair holds at the start of a game: a percentile draw is compared with `up_to` of the bands in order, and the first band the draw does not exceed gives the kind of loot. The rows are fixed; -1 keeps the original.

Built-in rows: band1, band2, band3, band4. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 4 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `up_to` | int | -1..100 | The highest draw (1..100) this band takes. |
| `loot` | enum | original, gold, items, mixed, none | What the lair holds: `gold` (a gold roll), `items` (three item rolls), `mixed` (a gold roll and two item rolls) or `none`. |

## places.ini - Places on the map

### `[place <name>]`

What the map nodes are. Arriving at a node whose number is in `node_first`..`node_last` of a row visits a place of that row's `kind`; a node in no row is not a place. The first row that matches wins. The kinds are the places of the game; a new row (`base = <row>`) can give another node the visit of an existing kind.

Built-in rows: village, town_a, town_b, stonehenge, valley, wizard, duel. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 12 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `node_first` | int | 0..255 | The lowest map node number of the row. |
| `node_last` | int | 0..255 | The highest map node number of the row. |
| `kind` | enum | none, village, town_a, town_b, stonehenge, valley, wizard, duel | What the node is: a castle village (a life and the temple), the two towns, Stonehenge, the Valley of the Gods, the wizard's house, the duel place, or `none`. |

### `[map_node <name>]`

The nodes of the map: the places a knight can walk to (the node table of the game). The rows are named by the node number in hexadecimal. A -1 keeps the position of the original data.

Built-in rows: n15, n16, n17, n18, n19, n1a, n1c, n1b, n1e. A new row: a name that does not exist yet, with `base = <existing row>` as its first key (at most 9 rows in total).

| key | type | allowed | meaning |
|---|---|---|---|
| `x` | int | -1..351 | Map x of the node (the knight arrives when it is on this spot). |
| `y` | int | -1..199 | Map y of the node. |

## rules.ini - Rule switches

### `[waves]`

Monster waves of the lair fights.

| key | type | allowed | meaning |
|---|---|---|---|
| `scaling` | enum | original, none, limited | How many monsters a lair fight has. `original`: the count grows with the knight's strength, maximum HP and attack damage, and so does the number of monsters alive at once. `limited`: only the total count grows (also written back to the lair), not the number alive at once. `none`: nothing grows. |

### `[coop]`

Two knights playing together (co-op, ROADMAP M8). No effect in classic single knight play.

| key | type | allowed | meaning |
|---|---|---|---|
| `enabled` | bool | on, off (yes/no, true/false, 1/0) | Apply the co-op wave rules below to the fights. Off in classic single knight play; the co-op mode (ROADMAP M8) sets it. |
| `alive_bonus` | int | 0..4 | Extra monsters alive at the same time in a fight with two knights. |
| `total_factor` | int | 1..4 | Multiplier of the fight's total monster count (including the lair's count) with two knights. |
| `writeback_divisor` | int | 1..4 | The monsters left after a co-op fight are divided by this (rounded up) before they are written back to the lair, so the lair population stays consistent with `total_factor`. |

### `[limits]`

Limits of a knight's purse and quiver.

| key | type | allowed | meaning |
|---|---|---|---|
| `gold_cap` | int | 1..32767 | A knight's gold is cut to this value. |
| `dagger_cap` | int | 0..99 | Daggers a knight can carry; the smith sells no more once the knight has this many. |

| `multiplier` | int | 1..255 | The winnings are the bet times this. |
