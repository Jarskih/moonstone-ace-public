# Byte order for the PC version (ROADMAP 11.3)

The original is a big-endian 68k; the PC build (M11, x86) is little-endian. The same source must give the same game.

## 1. The rule

Two kinds of memory exist:

* **Native memory**: C++ objects (u16 / u32 members, the structs of `include/game/*.hpp`, the typed cells of the owned data
  images). Accessed with the C++ types only; nobody looks at their bytes.
* **Big-endian bytes**: what the original defines as a byte stream (files, hunks, script bytecode, cel / picture headers,
  draw lists, the arena obstacle table, chip RAM). Read and written with `include/engine/endian.hpp`
  (`be::ld16/ld32/st16/st32`, byte compositions: same result on every CPU, no alignment need). On the 68k they compile to
  what the hand-written `rd16/rd32` before them compiled to.

A byte offset into a native struct with the 68k meaning (fight scripts `poke`/`ifzero`, mods) goes through
`include/game/record.hpp` (`recGet8/16/32`, `recSet8/16/32` over `kKnightCells`): byte 63 is the low byte of the word at +62 on
every CPU. On the 68k these are the plain pointer accesses they replace.

Slots (`ByteSlot`, `WordSlot`, `include/game/world.hpp`) are struct members: the first member is the part at the label
address on every CPU; `beWord()` / `beLong()` give the value the 68k sees reading the whole DS.

## 2. Data images (the 10.2a start-up loader)

`tools/gen_data.py` cuts every owned DATA object into members; the start-up fill (`engine/origfill`, `rt/origload`) copies the
original's big-endian bytes into them. Native cells (u16 / u32) must be byte-swapped on a little-endian CPU, byte blobs must not.
The unit of a member is decided by `tools/data_units.yaml`:

* `direct:` GENERATED by `py tools/endian_scan.py --write-units` from the IRA listing: a label reached by a direct operand
  (`MOVE.W LAB_05C5,D0`) is a scalar cell, unit = narrowest access width (a DS.L touched as .W = two u16 halves, so "the
  word at the label" is the high half on every CPU).
* `curated:` by hand, wins; for tables the asm reaches by address and the C++ reads as u16 / u32 arrays. The list grows with every table the PC play test (tests/pc_play) finds read as u16 / u32 (palettes,
  the wide-scene list, the creature spawn lists, the map node table ...).  Text list records (`DC.L text, DC.W x, y, style,
  DC.L next`) need no entry: `tools/gen_data.py apply_units` cuts the three words between two pointers to u16 cells.
* everything else is byte data (u8 members; read with `be::`). Regions of `tools/data_types.yaml` swap by their row-struct field
  widths, unless `bytes: true` (the synth instrument records).

`gen_data` then cuts members to the unit and emits the fill table in two forms: `#if MS_BIG_ENDIAN` the merged runs of before
(the Amiga executable is unchanged), else runs cut at unit changes with `OrigFillRun::ubUnit`; `origFill` swaps unit-2/4 runs
after the CRC is checked. `OrigFillRun::uwHunk` became `ubHunk` + `ubUnit` (same 14 bytes).

Proof: `gen_data.endian_fill_check()` applies the blank table to the real executables with the LE swap and compares with the
compiled-in typed initialisers of the full generation: all plain data and text members equal (119 unit runs).

## 6. The scan (tools/endian_externs.py)

`py tools/endian_externs.py --full <owned_data.cpp of gen_data.py --full --target pc32 ...>` lists every owned-data symbol the C++ declares
(`extern uint16_t x[]`) whose element type disagrees with the generated member (u8 = big-endian bytes, u16 / u32 / pointer = native),
split by what the original image holds there: MISMATCH (non-zero image bytes the fill swaps or leaves: a real swapped value), state
(zero in the image, only the C++ writes and reads it), review (casts, `be::` on a native cell, different widths in different files),
address-only (declared as bytes, only the address is used). `--check` fails on a MISMATCH; `KNOWN_OK` in the script holds the reviewed ones.
Findings fixed at the root (ROADMAP 11.3): code-hunk cells and `DS.L` listed as `DC.W` were cut finer than their unit in
`data_units.yaml` (the unit only ever narrowed a member): `apply_units` now joins a member up to its unit (the rest is `<name>_w`),
which made the wipe tables, the map step table, `mogDragonSpeed`, `mogArenaRegion` ... native; the RNG seed table is read with
`mainRngSeedBe` (be::ld32); the stat / mystic row longs (`LAB_090A`, `LAB_095B/C`) are curated u32 by member name.
